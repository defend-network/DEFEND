DEFEND API deployment configuration
===================================

Set deployment values in the service environment or an approved secret manager
before starting the API. Never commit credentials, generated secrets, cookies,
invitation links, or reusable tokens to this file, Git, logs, frontend variables,
or audit metadata.

Persistent data and identity
----------------------------
- DEFEND_DATA_ROOT: persistent writable directory. Keep the same directory across
  restarts and back it up according to the deployment policy. Identity, visitor,
  conversation, and audit databases are created below this root.
- DEFEND_OWNER_USER: required non-empty owner login name.
- DEFEND_OWNER_EMAIL: required valid owner email. It must remain stable for the
  single bootstrapped owner identity.
- DEFEND_OWNER_PASS: required owner secret. Supply it only through the backend
  environment or secret manager; never expose it to the browser.
- DEFEND_ADMIN_SESSION_HOURS: optional admin-session lifetime in hours. Invalid
  values use 12 hours; the effective lifetime is bounded from 15 minutes to 7 days.
- DEFEND_ACCOUNT_SESSION_HOURS: optional account-session lifetime in hours. Invalid
  values use 12 hours; the effective lifetime is bounded from 15 minutes to 7 days.
- DEFEND_COOKIE_SECURE: keep true in the HTTPS deployment. Disabling it is only
  appropriate for an isolated local HTTP development environment.
- Admin, account, and activation throttles are bounded but process-local. Run one
  API worker for authoritative in-process limits or add a durable shared/upstream
  rate limiter when deploying multiple workers. Keep upstream responses generic.

Visitor identity and proxy trust
--------------------------------
- DEFEND_VISITOR_HMAC_KEY: required secret with at least 32 characters. Generate a
  high-entropy random value, store it in the backend secret manager, and keep it
  stable across restarts. Changing it breaks continuity of pseudonymous visitor
  correlation.
- DEFEND_TRUST_CLOUDFLARE: set to the literal value true only when requests reach
  the API through the trusted Cloudflare deployment. Every other value uses the
  direct peer address and ignores CF-Connecting-IP.
- Detailed connection telemetry retention is fixed at 90 days.

Public web and activation transport
-----------------------------------
- DEFEND_PUBLIC_WEB_ORIGIN: required public HTTPS web origin, with scheme and host
  only. Invitation credentials are appended as URL fragments and must never be
  placed in a path, query string, log, or audit record.
- DEFEND_CORS_ORIGINS: comma-separated allowlist of trusted web origins when the
  browser calls the API cross-origin. Do not use a wildcard with credentials.
- NEXT_PUBLIC_DEFEND_API_BASE: frontend-only API origin when same-origin rewrites
  are not used. This value is public and must never contain a secret.

Gmail invitation delivery
-------------------------
- DEFEND_GMAIL_SMTP_SECURITY: ssl or starttls only.
- DEFEND_GMAIL_SMTP_HOST: required non-empty SMTP host.
- DEFEND_GMAIL_SMTP_PORT: required integer from 1 through 65535; use the port that
  matches the selected SMTP security mode.
- DEFEND_GMAIL_SMTP_USERNAME: required Gmail SMTP account name; treat as sensitive
  operational configuration.
- DEFEND_GMAIL_APP_PASSWORD: required Gmail app password; backend secret only.
- DEFEND_GMAIL_SENDER: required valid sender address authorized for the Gmail
  account.
- DEFEND_GMAIL_SMTP_TIMEOUT: optional seconds, bounded from 1 through 60.
- Missing or invalid Gmail settings leave the account pending and return a one-time
  copyable activation link to the authorized administrator; they never activate
  the account automatically.

Core API process
----------------
- DEFEND_MODEL and DEFEND_MODEL_BACKEND: select the configured model and backend.
- DEFEND_API_PORT: optional listen port; the default is 8000.
- DEFEND_API_TOKEN: optional backend API bearer secret where that existing control
  is enabled; never expose it through NEXT_PUBLIC_* variables.
- DEFEND_UPLOAD_DIR: optional writable upload directory; otherwise it is derived
  from DEFEND_DATA_ROOT.

Safe secret generation
----------------------
- Generate DEFEND_VISITOR_HMAC_KEY and owner passwords with a cryptographically
  secure password-manager generator or operating-system CSPRNG. Use at least 32
  random characters for the HMAC key and a strong unique owner password.
- In PowerShell, RandomNumberGenerator.GetBytes followed by Base64 conversion is an
  appropriate CSPRNG workflow. Copy the generated result directly into the secret
  manager; do not paste it into source files, shell history, chat, or tickets.
- Obtain DEFEND_GMAIL_APP_PASSWORD from the provider's app-password workflow; do
  not reuse the Gmail account password.

Startup order
-------------
1. Provision the persistent data root and inject all required environment and
   secret-manager values into the API service account.
2. Start the configured model backend and verify it is ready.
3. From the repository root, start the API with:
     .\.venv\Scripts\python.exe api_server.py
4. Build and start the Next.js frontend with its public API-origin setting, then
   start the trusted Cloudflare tunnel routes.
5. Verify API health, owner login, invitation delivery/fallback copying, fragment
   activation, account login, and normal visitor linking before enabling traffic.
