DEFEND API - Control Center deployment names
============================================

Launch DEFEND with Start-DEFEND.cmd. Do not start the model, API, frontend, or
Cloudflare separately. The Control Center owns startup order, health checks,
rollback, and shutdown.

Store values through Setup only
-------------------------------
Identity/session:
- DEFEND_OWNER_USER
- DEFEND_OWNER_EMAIL
- DEFEND_OWNER_PASS
- DEFEND_VISITOR_HMAC_KEY
- DEFEND_ADMIN_SESSION_HOURS
- DEFEND_ACCOUNT_SESSION_HOURS
- DEFEND_ADMIN_LOGIN_HASH_CONCURRENCY

Gmail invitations:
- DEFEND_GMAIL_SMTP_SECURITY
- DEFEND_GMAIL_SMTP_HOST
- DEFEND_GMAIL_SMTP_PORT
- DEFEND_GMAIL_SMTP_USERNAME
- DEFEND_GMAIL_APP_PASSWORD
- DEFEND_GMAIL_SENDER
- DEFEND_GMAIL_SMTP_TIMEOUT

Remote model:
- VAST_API_KEY
- HF_TOKEN
- VLLM_API_KEY

Public routing:
- DEFEND_PUBLIC_WEB_ORIGIN
- DEFEND_TRUST_CLOUDFLARE
- DEFEND_CORS_ORIGINS
- NEXT_PUBLIC_DEFEND_API_BASE

Persistent policy
-----------------
- Keep C:\DEFEND_DATA stable and backed up.
- Connection telemetry retention is fixed at 90 days.
- Invitation credentials use URL fragments only.
- Process-local authentication limits require one API worker unless a shared
  upstream limiter is added.
- Run the Control Center's non-billable check before launch.
- Rotate every credential that ever appeared in source, terminal history, chat,
  screenshots, or logs before production acceptance.

Normal operation
----------------
1. Double-click Start-DEFEND.cmd.
2. Complete Setup if requested.
3. Select Local Ollama or Vast.ai.
4. Click Start DEFEND.
5. Use Stop Local for computer processes only. For Vast.ai, use Stop + Destroy
   Vast and confirm the exact instance ID to end remote billing.

See docs/operations/DEFEND-Control-Center.md for the complete runbook.
